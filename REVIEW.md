## Содержательные проверки

- Технические определения и банки вопросов не копируются. В технических главах — процесс кандидата, упражнение, артефакт и переход в Web-методичку.
- Проекты курса сверены по истории: текущий `docs/projects.md` удалён. В `project-to-portfolio.md` приведена рабочая ссылка на историческую редакцию.
- Finder и Desserts не объявлены React/TypeScript-проектами: исходный стек JavaScript/Vite указан честно. React-проект потока рассматривается отдельно.
- Для Desserts отмечена необходимость доступного API или честного demo-режима: JSON Server не запускается на статическом Pages автоматически.
- Дополнительные улучшения проектов не выдаются за обязательный список или уже выполненную работу читателя.
- Во всех 33 главах есть конкретные действия. В 11 шаблонах — явные якоря для прямых переходов.
- Учебные сообщения не советуют придумывать компании, метрики, стаж, зарплату и вклад.
- Слово backend встречается в допустимом контексте: дополнительная PHP-траектория и реальный URL учебного раздела. Слово JavaScript относится к целевому стеку. Исторические имена удалённых файлов упоминаются только в этом отчёте.
- Числа рынка и налоговые расчёты исходника не перенесены. Зарплатные главы сохраняют процесс сбора ориентиров, переговоров и проверки условий.

## Воспроизводимые проверки

```bash
python3 scripts/docs.py check
.venv/bin/python scripts/check_theory_links.py
.venv/bin/python -m pip check
git diff --check
```

`check` проверяет все Markdown-страницы в nav ровно один раз, строгую сборку, локальные ссылки, якоря и ресурсы. Внешний скрипт делает GET всех уникальных URL технической методички, проверяет HTTP, заголовок статьи и якорь, если он указан. Исходная проверка номеров удалённых технических банков заменена защитой от их возврата.

Результаты локальной и опубликованной проверки фиксируются после выполнения; наличие команд само по себе не означает успешный deploy.
