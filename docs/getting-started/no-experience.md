# Первая работа без коммерческого опыта

**Нет коммерческого опыта → показываем проект.** Работодателю нужно увидеть, что вы способны выполнить ограниченную задачу, проверить её и объяснить решение. Не придумывайте работодателя, стаж, оплату или результаты.

## Что доказывает проект

| Навык | Доступное доказательство |
|---|---|
| Верстка | Страница с desktop/mobile и работающими формами |
| JavaScript | Законченный пользовательский сценарий и обработка некорректного ввода |
| React и состояние | Собственное изменение приложения, которое можете объяснить и повторить |
| Работа с API | Успех, загрузка, ошибка и пустой результат |
| Git и завершение задачи | Понятная история, README, доступное demo |

React/TypeScript-приложение с API, routing, формой и адаптивом может быть сильным кейсом. Не нужно добавлять всё в каждый проект. Один законченный сценарий полезнее пяти недоделанных приложений.

## Какие виды опыта допустимы

Подойдут учебный, личный, университетский, командный проект, реальный open source или фриланс, если он действительно был. Предыдущую работу вне IT используйте для историй об общении, дедлайнах и ответственности; она не превращается в стаж Frontend-разработки.

В CV используйте блок «Учебные и личные проекты». В командной работе укажите свою часть. Для проекта курса назовите основу и самостоятельные изменения. Если помогали преподаватель или AI, умейте показать, что проверили и можете изменить самостоятельно. Не присваивайте чужой код целиком.

## Пример вместо вымышленного стажа

> Учебный проект GitHub User Finder. Доработал поиск профилей: обработал отсутствие пользователя и лимит API, добавил отмену устаревшего запроса и сохранение темы. Ссылки на код и demo. Основа — проект курса; перечисленные изменения выполнил самостоятельно.

Так пишите только после реального выполнения. Исходный Finder был на JavaScript/Vite: называйте React или TypeScript только при собственной подтверждаемой переработке.

## Начните с ограниченного результата

Выберите [проект курса](../resume/project-to-portfolio.md), доработайте одну важную проблему и оформите [карточку](../templates/index.md#project-card). Если основы мешают изменению, повторите конкретную тему в [учебной методичке](https://itpark32.github.io/web-14-metodichka/interview/), затем возвращайтесь к практике и откликам.

## Что сделать прямо сейчас

1. Выберите один проект, закрывающий три требования вакансии.
2. Отделите учебный, личный и коммерческий опыт.
3. Запишите личный вклад и ограничения.
4. Найдите пять подходящих стартовых позиций.
5. Начните недельный план, не дожидаясь идеального портфолио.
