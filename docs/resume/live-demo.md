# Live demo проекта

Demo позволяет открыть Frontend-приложение прямо из резюме. Его задача — быстро показать работающий сценарий без установки среды и запроса доступа.

## Выбрать способ публикации

Для статической сборки можно рассмотреть [GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages). Для других платформ сначала проверьте текущие ограничения и правила. Этот handbook не обещает бесплатность или поддержку сервера конкретным тарифом.

GitHub Pages размещает статические файлы: PHP, Laravel и JSON Server требуют отдельной среды. Frontend и API можно разместить отдельно; README должен объяснять, откуда берутся данные и сохраняются ли изменения. Не скрывайте mock-режим.

## Проверить именно опубликованную сборку

| Проверка | Как проверить |
|---|---|
| Доступ и HTTPS | Открыть ссылку в приватном окне без входа в аккаунт |
| Путь приложения | Перейти по ссылке из README; проверить CSS, JS и изображения |
| Вложенный маршрут | Вставить адрес страницы напрямую и обновить её |
| API | Пройти основной сценарий, посмотреть Network и сообщение об ошибке |
| Состояния | Медленная сеть, ошибка, пустой результат и восстановление |
| Mobile | Узкий экран и реальный телефон, если доступен |
| Console | Нет ошибок приложения и незагруженных ресурсов |
| Переменные | Нужная конфигурация задана при сборке, секретов нет |

Если SPA-маршрут при refresh даёт 404, выберите поддерживаемую хостингом стратегию маршрутизации и проверьте её до отклика. Если сайт находится в подпапке, проверьте базовый путь ресурсов. Детали — в [блоке браузера и инструментов](https://itpark32.github.io/web-14-metodichka/interview/browser-tools/).

## Перед отправкой

Поместите repo и demo рядом в CV и README, добавьте screenshot как быстрый обзор. Укажите ограничения API и тестовую учётную запись только для изолированных учебных данных, если вход действительно необходим. Не размещайте пароль от личного аккаунта.

Если внешний API временно недоступен, приложение должно показывать понятное сообщение. Screenshot полезен как дополнение, но не заменяет проверку рабочего demo.

## Что сделать прямо сейчас

1. Опубликуйте production-сборку по инструкции выбранного хостинга.
2. Откройте demo без авторизации и обновите вложенную страницу.
3. Проверьте сеть, console, mobile и ошибочное состояние.
4. Добавьте проверенную ссылку в README, карточку и CV.
