# Примеры Frontend-формулировок

Ниже учебные образцы, а не достижения для копирования. Используйте пункт только после выполнения и проверки соответствующей работы. Формула: **действие → сценарий → проверка или ограничение**.

| Тема | Слабо | Конкретнее |
|---|---|---|
| Верстка | HTML/CSS | Сверстал каталог по Figma, адаптировал сетку и форму для узкого экрана, проверил клавиатурную навигацию |
| JavaScript | Писал JS | Реализовал ввод калькулятора и обработку некорректных значений; проверил повторное нажатие `=` |
| React | Знаю React | Разбил каталог на компоненты, организовал состояние корзины и проверил синхронизацию количества и суммы |
| API | Подключил API | Добавил поиск профилей, loading/error и отмену устаревших запросов; проверил быстрый повторный поиск |
| TypeScript | Знаю TS | Типизировал модель товара и состояния запроса, убрал неявные any в изменённом модуле |
| Качество | Тестировал | Добавил тест расчёта корзины и проверку пустого списка; описал ручные сценарии demo |
| Производительность | Оптимизировал | Нашёл тяжёлое изображение в Network, заменил ресурс и повторил измерение при тех же условиях |

## Пример краткого профиля

> Начинающий Frontend-разработчик, выпускник Web-курса IT-ПАРК. В учебных проектах создавал адаптивные интерфейсы и подключал API. В собственном React-проекте реализовал форму и обработку ошибок. Ищу Junior/Intern-позицию с review и наставником.

Уберите React, если собственного проекта на нём пока нет. Вместо «быстро обучаюсь» назовите самостоятельное изменение и способ его проверки.

## Когда нужны числа

Не пишите «ускорил сайт на 70%», если измерений не было. Запишите исходный и новый результат, инструмент, устройство, условия сети и число запусков. Лабораторный Lighthouse-балл не выдавайте за результат реальных пользователей.

Если улучшение не завершено, формулируйте границу: «основной сценарий работает; серверная авторизация не реализована». Отрицательный результат полезен, когда вы объясняете причину и следующий шаг.

## Проверьте фразу вопросами интервьюера

«Что сделали лично? Где это видно? Как проверить? Почему этот вариант? Что не получилось?» Если ответы расплывчаты, вернитесь к [карточке проекта](../templates/index.md#project-card). Для повторения механизма используйте [Web-методичку](https://itpark32.github.io/web-14-metodichka/interview/).
