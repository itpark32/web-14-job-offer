# Резюме Frontend-разработчика

Результат главы — опубликованное резюме и читаемый PDF, из которых понятно, какую Frontend-задачу вам можно поручить. Для первого CV обычно достаточно одной страницы; вторая нужна, если на ней есть релевантные факты.

## Порядок для кандидата без опыта

| Блок | Содержание |
|---|---|
| Целевая роль | Junior Frontend Developer или близкое конкретное название |
| Контакты | Имя, город, часовой пояс, почта/телефон, GitHub и портфолио |
| Краткий профиль | 3–5 строк: учебный контекст, задачи, цель |
| Стек | Только применённые и объяснимые инструменты |
| Учебные и личные проекты | 1–2 сильных кейса, личный вклад, repo и demo |
| Обучение | Web-курс IT-ПАРК и релевантное образование |
| Предыдущая работа | Кратко, если подтверждает полезные навыки |

Не маскируйте проекты под место работы. Не добавляйте паспорт, домашний адрес, чужие контакты или незнакомые технологии ради поиска.

## Контекст → личное действие → проверяемый результат

**Слабо:** «Знаю React, Redux, JavaScript, TypeScript».

**Конкретнее, если действительно сделали:** «В учебном каталоге на React реализовал корзину, разделил UI и сетевой слой, добавил loading/error и сохранение корзины между сессиями. Проверил добавление, удаление и восстановление после перезагрузки».

Для командного проекта: «Команда сделала каталог; я отвечал за адаптив карточек, форму поиска и её состояния». Не присваивайте работу всей команды.

Достоверная качественная формулировка лучше придуманного процента. Измерения добавляйте с условиями и базой сравнения. Ещё примеры — в [банке формулировок](examples.md).

AI можно использовать как редактора формулировок, но не как источник опыта и фактов — см. [правила использования AI](../job-search/ai.md).

## Опубликовать и проверить

На площадке заполните одну роль, реальные навыки и условия. Проверьте видимость контактов и доступность ссылок для постороннего пользователя. Факты в профиле и PDF должны совпадать; для отдельной PHP-траектории подготовьте другую версию.

Экспортируйте текстовый PDF, а не скриншот страницы. Откройте его на телефоне, проверьте выделение текста и переходы. Назовите файл `Имя_Фамилия_Frontend_2026.pdf`. Запишите версию CV в трекер, например `frontend-v1`.

## Быстрая редакторская проверка

- [ ] Заголовок отвечает выбранной роли.
- [ ] Проекты заметны на первом экране.
- [ ] Каждый пункт можно защитить вопросом «покажите в коде».
- [ ] Учебный контекст и личный вклад обозначены.
- [ ] Контакты, даты, repo и demo открываются.
- [ ] В PDF нет обрезанного текста и пустой второй страницы.

Технические пробелы устраняйте по [карте подготовки](../technical/developer.md), а не скрывайте формулировкой CV.

## Что сделать прямо сейчас

1. Соберите факты по двум проектам.
2. Отредактируйте заголовок и три сильных пункта.
3. Опубликуйте CV и сохраните PDF с версией.
4. Попросите одногруппника за минуту назвать ваши сильные задачи.
