# Как превратить учебный проект в портфолио

Не переписывайте весь проект. Проверьте основной сценарий, обозначьте учебную основу и добавьте одно самостоятельное улучшение, которое сможете защитить.

Названия и исходные возможности сверены с [исторической страницей проектов потока](https://github.com/itpark32/web-14-metodichka/blob/9a9aa3e/docs/projects.md). В текущей редакции учебной методички эта страница удалена, поэтому ссылки на несуществующий маршрут `/projects/` здесь нет. История — источник контекста курса, а не текущая техническая документация.

## Выберите улучшение по проблеме

| Проект курса | Что показать работодателю | Идеи следующего шага, не обязательный список |
|---|---|---|
| Северяночка | Адаптивный каталог и семантическую навигацию | Проверить клавиатуру, чистоту CSS и Lighthouse; опубликовать demo |
| Clean portfolio | Самостоятельную адаптацию шаблона | Заменить учебные данные, указать происхождение, проверить mobile и лишние зависимости |
| Simple Calculator | Законченную работу с вводом | Управление клавиатурой, некорректный ввод, повторное `=`, список тест-кейсов |
| Угадай число | Понятные состояния игры | Проверка диапазона и дробного ввода, победа/поражение, перезапуск без перезагрузки |
| Posts App | Сценарий входа и просмотра постов | Проверить прямой вход по URL, ошибки API и разграничить учебную имитацию входа и серверную защиту |
| Desserts | Каталог и корректную корзину | Loading/error/empty, тест суммы, при необходимости optimistic update с восстановлением после ошибки |
| GitHub User Finder | Поиск профиля и работу с сетью | AbortController, обработка лимита API и отсутствия пользователя, сохранение темы, responsive |
| React-проект потока / Lesson 24 | Собственное развитие небольшого приложения | Форма, стабильность списка, объяснимое состояние и тест пользовательского сценария |

## GitHub User Finder: законченный кейс

Исходная работа — JavaScript/Vite и GitHub API. Не называйте её React/TypeScript-проектом без реальной миграции. Добавьте README, screenshot и demo, затем проверьте: неизвестный пользователь, медленная сеть, два быстрых поиска и исчерпанный лимит. Не публикуйте личный токен ради обхода лимита.

В CV можно описать только реализованное: «В учебном Finder добавил обработку ошибки и отмену устаревшего поиска; проверил быстрый ввод двух имён». Сохраните шаги проверки и объясните, почему это улучшает сценарий.

## Desserts: сначала доступность данных

Исходный проект использовал JSON Server. Локальный сервер не появится на статическом хостинге автоматически. Для demo выберите доступный API, отдельно размещённый сервер или явно обозначенный режим с тестовыми данными. Покажите ограничения записи. До отправки проверьте, что корзина и сумма остаются согласованными.

Optimistic update и дополнительные тесты — варианты развития, если основной сценарий уже надёжен. Не обещайте реальные заказы или оплату в учебной версии.

## Северяночка: качество вместо нового стека

Покажите один и тот же сценарий на desktop и mobile, проверьте меню, поля и кнопки с клавиатуры. Сохраните screenshot и результаты аудита с условиями. Не превращайте хорошую верстку в срочную React-перепись ради заголовка CV.

Для каждой работы завершите [карточку проекта](../templates/index.md#project-card) и [проверку demo](live-demo.md). Технические детали повторяйте по [HTML/CSS](https://itpark32.github.io/web-14-metodichka/interview/html-css/), [JavaScript](https://itpark32.github.io/web-14-metodichka/interview/javascript/) или [React](https://itpark32.github.io/web-14-metodichka/interview/react/).

## Что сделать прямо сейчас

1. Выберите один проект и одну проблему пользователя.
2. Ограничьте доработку сроком и критерием готовности.
3. Проверьте изменение на обычном и ошибочном сценарии.
4. Добавьте личный вклад, screenshot и ограничения в README.
5. Опубликуйте demo и обновите пункт CV.
