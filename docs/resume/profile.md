# GitHub-профиль Frontend-разработчика

Профиль связывает резюме с доказательствами. Работодатель должен найти подходящий проект и открыть его без переписки о доступе.

## Первый экран профиля

Укажите выбранную роль, короткое описание и рабочий контакт. Закрепите 2–3 объяснимых репозитория; если готовы только два, не заполняйте остальные места незавершёнными копиями уроков. Название роли и факты должны совпадать с CV.

Называйте репозитории по задаче: `github-user-finder`, а не `lesson-final-final`. Добавьте описание и ссылку demo. Не меняйте историю ради количества коммитов: «зелёные квадраты» не доказывают качество.

## Что должно быть в README

1. Пользовательская задача и основной сценарий.
2. Demo и screenshot, включая мобильный вид при необходимости.
3. Реальный стек и 2–3 решения с причинами.
4. Точная версия среды, установка, запуск, сборка и проверки.
5. `.env.example` без секретов, если нужны переменные.
6. Личный вклад, основа курса/шаблона, ограничения.

Пройдите инструкцию в новой папке. Не рассчитывайте на локальный JSON Server или файлы, которых нет в репозитории. Нормальная история Git показывает понятные изменения; не создавайте вымышленную историю разработки.

## Публичность и безопасность материалов

Не публикуйте рабочий код, данные клиентов и токены. Секрет в браузерной сборке доступен посетителю независимо от имени переменной. Если ключ попал в публичную историю, отзовите его и замените: удаления строки в последнем коммите недостаточно.

В командной работе укажите авторов и свою часть. Если использовали шаблон или AI, объясните самостоятельные изменения и их проверку. Умейте внести небольшое изменение без подсказки.

## Проверка посторонним человеком

Попросите одногруппника пройти от CV до demo, запустить код по README и назвать вашу часть работы. Запишите места, где понадобились устные пояснения, и исправьте документацию.

Дальше — [портфолио](portfolio.md), [упаковка проекта курса](project-to-portfolio.md) и [проверка live demo](live-demo.md). Технический Git повторяйте в [учебной методичке](https://itpark32.github.io/web-14-metodichka/interview/browser-tools/).

## Что сделать прямо сейчас

1. Проверьте профиль в приватном окне.
2. Закрепите 2–3 лучших репозитория.
3. Дополните README главного проекта и screenshot.
4. Проверьте запуск по инструкции в новой папке.
