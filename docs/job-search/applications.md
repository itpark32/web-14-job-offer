# Отклики и job tracker

Цель отклика — начать разговор о подходящей работе. Используйте [разбор вакансии](read-vacancy.md), адаптируйте правдивые материалы и сразу фиксируйте следующий шаг.

## Адаптация без выдумок

1. Выпишите три главные задачи вакансии.
2. Подберите свои ближайшие примеры и поднимите их выше в CV.
3. Проверьте заголовок, repo и demo.
4. Назовите существенный пробел честно; не добавляйте незнакомый инструмент.
5. Запишите версию CV, чтобы потом сравнивать результат.

Не нужно 100% совпадения с пожеланиями. Жёсткий конфликт формата и отсутствие основного навыка требуют отдельного решения, а не массовой отправки.

## Пример сопроводительного сообщения

> Здравствуйте! Откликаюсь на Junior Frontend Developer. В учебном GitHub User Finder на JavaScript/Vite работал с GitHub API, добавил loading/error и отмену устаревших запросов. Это близко вашей задаче поиска по внешнему API. Repo: [ссылка]. Demo: [ссылка]. CV: [ссылка]. Готов обсудить личный вклад и ограничения.

Пример предполагает, что изменения действительно выполнены. Для React-вакансии выберите реальный React-проект; не переименовывайте стек Finder. Письмо должно связывать один ваш факт с задачей компании, а не пересказывать биографию.

## Поля трекера

Одна строка — одна вакансия, даже если встретили её в нескольких каналах. Скачайте [CSV](../templates/job-tracker.csv).

| Поле | Как заполнять |
|---|---|
| Компания, вакансия, ссылка, источник | Оригинальное объявление и его ID |
| Дата, версия CV | Дата отклика и отправленный вариант |
| Основные требования | 2–3 задачи и своё соответствие |
| Этап | Один из согласованных статусов |
| Следующее действие, дата следующего действия | Конкретное действие и срок |
| Результат, причина отказа | Факт; «неизвестна», если причину не сообщили |

Статусы: **Найдено → Отклик → HR → Техническое интервью → Тестовое → Финал → Оффер → Принято**. Не все этапы обязательны. Отдельные исходы: **Отказ компании, Отказ кандидата, Вакансия закрыта, Ожидание**. Для ожидания сохраните последний пройденный этап в заметке.

## Рабочий ритм

Начните с небольшой релевантной группы, которую успеете обработать. Для каждого открытого процесса назначьте дату следующего действия. Не храните в общей таблице документы и закрытые материалы работодателя.

Раз в неделю анализируйте завершённые этапы и отдельно ожидаемые решения. Если ответов нет, проверяйте соответствие вакансий и материалы по [диагностике воронки](rejections.md). Если срок ответа прошёл — используйте [follow-up](follow-up.md).

## Что сделать прямо сейчас

1. Адаптируйте CV под близкую группу Frontend-ролей.
2. Напишите письмо с одним подтверждаемым примером.
3. Отправьте первые релевантные заявки.
4. Для каждой заполните tracker и дату действия.
