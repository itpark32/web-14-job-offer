# Frontend-тестовое: от условия до защиты

Результат — воспроизводимое приложение, repo, demo и понятное описание решений. Сначала согласуйте границы, затем доведите обязательный сценарий до конца.

## 1. Разберите условие до кода

Создайте таблицу «обязательно / дополнительно / неизвестно». Для каждого обязательного требования запишите наблюдаемый критерий готовности.

| Требование в учебном задании | Критерий проверки |
|---|---|
| Каталог из API | Список отображается после запроса |
| Поиск | Обычный и пустой результат работают |
| Корзина | Добавление, удаление и итог согласованы |
| Адаптив | Основной сценарий выполняется на узком экране |
| Качество | Понятные состояния, чистая сборка, README и demo |

Не добавляйте авторизацию, сложную архитектуру и новую UI-библиотеку без необходимости. Если часть условия противоречива, уточните её письменно. До ответа зафиксируйте допущение, которое можно изменить.

Спросите срок, ожидаемые затраты времени, критерии, требования к стеку, данные, возможность публикации repo/demo, правила AI и наличие защиты. Для большого объёма предложите ограниченный кейс, разбор портфолио или оплату. Не публикуйте закрытое условие без разрешения.

## 2. Оцените время и порядок

Разбейте работу на: основной сценарий → состояния → адаптив и доступность → проверки → README и deploy. Оставьте отдельный резерв на чистый запуск. Это план, который нужно сверить с заданием, а не обязательная часовая норма.

Пример сообщения: «Уложусь в согласованный срок для каталога, поиска и состояний API. Историю заказов считаю дополнительной и опишу как ограничение. Верно ли понял приоритеты?»

## 3. Сначала рабочий минимум

Соберите путь пользователя от входа до результата. После этого добавьте loading, error и empty, повтор запроса и граничные данные. Проверьте быстрые действия и согласованность состояния. Не прячьте сбой под бесконечным spinner.

Проверьте mobile, подписи полей, видимый фокус и выполнение сценария с клавиатуры. Посмотрите Console и Network. Напишите осмысленные проверки наиболее важного поведения: например, сумма корзины или повтор после ошибки. Не измеряйте качество количеством тестов.

Механизмы повторяйте в [React](https://itpark32.github.io/web-14-metodichka/interview/react/), [браузере и инструментах](https://itpark32.github.io/web-14-metodichka/interview/browser-tools/) и [качестве](https://itpark32.github.io/web-14-metodichka/interview/quality/).

## 4. README и чистый запуск

Укажите назначение, реальный стек, версии среды, установку, запуск, сборку, проверки, переменные, demo и ограничения. Отдельно опишите архитектурное решение и альтернативу, на что не хватило времени и почему.

Склонируйте работу в новую папку. Выполните ровно команды README: `npm install`, либо `npm ci` при согласованном lock-файле, затем `npm run build` и предусмотренные проверки. Проверяйте и production-сборку, а не только dev server.

```text
[ ] npm install работает (или документированный npm ci)
[ ] npm run build работает
[ ] README и точная инструкция есть
[ ] .env.example есть, если нужны переменные
[ ] demo открывается без личного аккаунта
[ ] основной сценарий завершён
[ ] mobile и клавиатура проверены
[ ] loading, error и empty проверены, где применимы
[ ] console без ошибок
[ ] секретов и закрытых данных нет
[ ] ограничения и компромиссы описаны
```

Если публичный deploy запрещён, согласуйте разрешённый способ передачи и демонстрации. Не нарушайте условия ради галочки «demo».

## 5. Отправьте результат и подготовьте защиту

```text
Здравствуйте! Отправляю тестовое по Junior Frontend [ID].
Repo: [ссылка] / Demo: [разрешённая ссылка].
Готово: [обязательные сценарии]. Проверено: [команды и сценарии].
Ограничения: [честный список], причины и решения описаны в README.
Готов обсудить выбор подхода и внести небольшое изменение на защите.
```

Отправляйте в согласованный канал и срок. Не оставляйте проверяющему задачу найти нужную ветку. Запишите commit/версию сдачи в tracker.

На защите покажите путь пользователя, личное решение и компромисс. Подготовьте [короткий и подробный рассказ](project.md). Если использовали AI по правилам компании, объясните его роль и собственную проверку кода.

## Что сделать прямо сейчас

1. Выделите обязательный сценарий и критерии.
2. Согласуйте неизвестное, время и способ передачи.
3. Составьте план с резервом на проверку и deploy.
4. Проверьте результат из новой папки по README.
5. Сохраните commit сдачи и отрепетируйте защиту.
